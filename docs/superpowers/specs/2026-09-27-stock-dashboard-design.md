# 개인 주식 대시보드 설계 (v1)

- 작성일: 2026-09-27
- 상태: 사용자 검토 대기

## 1. 목적과 범위

내 PC에서만 여는 **미국 주식 포트폴리오 대시보드**. 보유 종목의 수량·평단가를 입력하면 실시간 시세로 평가손익과 비중을 보여주고, 보유 종목의 실적발표일과 직접 넣은 일정을 디데이로, 최근 뉴스를 목록으로 보여준다.

**성공 기준:** 서버를 켜고 브라우저로 열면 몇 초 안에 총 평가금액, 총 손익, 비중 그래프, 가장 가까운 실적발표 디데이가 한 화면에 보인다.

### 확정된 결정

| 항목 | 결정 |
|---|---|
| 실행 환경 | 내 PC 로컬 전용. 서버는 `127.0.0.1`에만 바인딩(같은 네트워크의 다른 기기 접속 불가) |
| 시장 | 미국 주식만. 금액은 달러, 합계에 원화 환산 한 줄 |
| 손익 | 현재 보유분 기준 평가손익(종목별·합계·오늘 등락) |
| 시세 갱신 | 미국 장중 30초 자동 새로고침, 장외에는 자동 갱신 중지 |
| 디데이 | 보유 종목 실적발표일(자동) + 직접 넣는 일정 |
| 뉴스 | 영어 제목 + 출처 + 원문 링크 |
| 색상 | 한국식: 상승·이익 = 빨강, 하락·손해 = 파랑 |
| 데이터 소스 | Finnhub 무료 API(키 필요), 환율은 Frankfurter(키 불필요) |
| 저장 | 로컬 파일 `data/portfolio.json`, API 키는 `.env` |

### v1에서 제외

매매 기록·실현손익·세금, 배당 일정, 한국 주식, 휴대폰·외부 접속, 틱 단위 실시간(WebSocket), 뉴스 한국어 요약, 가격 알림, 다중 사용자.

## 2. 보안·개인정보

- 수량·평단가는 `data/portfolio.json`과 브라우저 사이에서만 오간다. 외부로 나가는 것은 **조회하는 티커**뿐이다(Finnhub가 어떤 종목을 조회하는지는 안다).
- Finnhub API 키는 `.env`에만 두고 서버만 읽는다. 프론트엔드 코드와 API 응답에 키를 넣지 않는다.
- `.env`와 `data/`는 `.gitignore`에 포함한다. 저장소가 공개되어도 키와 보유 내역은 올라가지 않는다.
- 서버 기본 바인딩은 `127.0.0.1`이며, 바인딩 주소는 코드에 고정한다(설정으로 `0.0.0.0`을 열지 않는다).

## 3. 화면 구성

넓은 화면에서는 왼쪽에 포트폴리오(①②③), 오른쪽에 일정·뉴스(④⑤)를 둔다. 창 폭이 좁으면(약 1000px 미만) 오른쪽 패널이 아래로 내려가 한 열로 쌓인다.

```
┌──────────────────────────────────────────────────────────────┐
│ 내 포트폴리오      장중 · 14:32:05 갱신 (30초마다)  [⟳] [+ 종목 추가] │
├────────────────────────────────────────┬─────────────────────┤
│ ① 요약: 총 평가금액 · 총 손익 · 오늘 등락 · 원화 환산 │ ④ 디데이 (90일)      │
├────────────────────────────────────────┤   [+ 일정 추가]       │
│ ② 보유 종목 표                           ├─────────────────────┤
├────────────────────────────────────────┤ ⑤ 뉴스 (최근 7일)     │
│ ③ 도넛(평가금액 비중) · 막대(종목별 손익)    │   [종목 필터]         │
└────────────────────────────────────────┴─────────────────────┘
```

- **① 요약 카드:** 총 평가금액(USD), 총 평가손익(금액·%), 오늘 등락(금액·%), 원화 환산 총액("기준환율" 표기).
- **② 보유 종목 표:** 열은 종목(티커·회사명), 수량, 평단가, 현재가, 오늘 등락률, 평가금액, 평가손익(금액·%), 비중. 열 제목 클릭으로 정렬한다. 행마다 [수정] [삭제]가 있고, 삭제 전에는 화면 안에서 확인을 받는다.
- **[+ 종목 추가]:** 티커·수량·평단가를 입력하는 모달. 저장 전에 서버에서 티커가 실제로 있는지 확인한다.
- **③ 비중 그래프:** 도넛 차트는 종목별 평가금액 비중(%), 막대 차트는 종목별 평가손익 금액. 막대 색은 한국식 규칙을 따른다.
- **④ 디데이:** 오늘부터 90일 안의 일정을 가까운 순으로 보여준다.
  - 실적발표: `D-3 SOFI 실적 (장전) · 예상 EPS $0.12 · 한국시간 약 10/30 밤`
  - 직접 입력: 제목·날짜·메모(선택). 수정·삭제할 수 있다.
  - 당일은 `D-DAY`로 표시한다.
- **⑤ 뉴스:** 보유 종목의 최근 7일 기사. 종목당 최신 5개를 모아 시간 역순으로 보여준다. 항목에는 티커·출처·상대시간·제목이 있고, 클릭하면 원문이 새 탭에서 열린다. 종목 필터(전체/종목별)가 있다.
- **상단 상태 표시:** `장중 · HH:MM:SS 갱신` / `장 마감 · 종가 기준` / `지연 · 마지막 갱신 HH:MM`. [⟳]는 즉시 전체 새로고침.

## 4. 갱신 규칙

| 데이터 | 브라우저 요청 주기 | 서버 캐시 TTL |
|---|---|---|
| 시세 | 장중 30초, 장외 자동 중지(수동 새로고침만) | 15초 |
| 장 상태 | 60초 | 60초 |
| 뉴스 | 30분 | 30분 |
| 실적 일정 | 30분 | 6시간 |
| 환율 | 30분 | 6시간 |
| 회사명(티커 확인) | 종목 추가 시 | 24시간 |

호출량: 종목 20개 기준 시세는 분당 약 40회로, Finnhub 무료 한도(분당 60회) 이내다. 서버는 동시에 들어온 같은 요청을 하나로 합치고, 한도 초과(429)가 나면 백오프한다.

## 5. 아키텍처

```
브라우저(localhost) ──/api──▶ Node 서버(127.0.0.1) ──HTTPS──▶ Finnhub / Frankfurter
                                   │
                        data/portfolio.json · .env
```

- **런타임:** Node.js 24 (내장 `fetch`, 내장 테스트 러너 `node:test` 사용)
- **서버 의존성:** Express
- **프론트엔드:** 프레임워크 없는 HTML/CSS/ES 모듈 + Chart.js(npm으로 설치해 로컬에서 제공, CDN 미사용)
- **실행:** `npm start` → 콘솔에 `http://127.0.0.1:<PORT>` 출력

### 폴더 구조

```
Stock/
├─ server/
│  ├─ app.js        # createApp(): 라우트·정적 파일·오류 처리
│  ├─ index.js      # 진입점: 127.0.0.1 바인딩, 포트 충돌 안내

│  ├─ cache.js      # 범용 TTL 캐시(마지막 성공 값 보관)
│  ├─ store.js      # portfolio.json 읽기/검증/원자적 쓰기
│  ├─ market.js     # 미국 장 상태 판정(뉴욕 시간, 서머타임, 휴장일)
│  └─ fx.js         # USD/KRW 환율(Frankfurter)
├─ public/
│  ├─ index.html, styles.css
│  ├─ app.js        # 초기화·새로고침 스케줄러·상태 표시
│  ├─ setup.js      # 대화상자·차트·디데이·뉴스를 app.js에 연결
│  ├─ api.js        # /api 호출 래퍼
│  ├─ forms.js      # 종목·일정 입력 대화상자, 삭제 확인
│  ├─ calc.js       # 손익·비중 계산 (순수 함수)
│  ├─ format.js     # 금액·퍼센트·시간 표시 (순수 함수)
│  ├─ dday.js       # 디데이·한국시간 변환 (순수 함수)
│  └─ views/        # dom.js, summary.js, holdings.js, charts.js, events.js, news.js
├─ tests/           # 단위·라우트 테스트

```

각 모듈의 역할:

- `calc.js`와 `dday.js`는 DOM이나 네트워크에 의존하지 않는 순수 함수로 두어 단독으로 테스트한다.
- `finnhub.js`는 `fetch`를 주입받아 테스트에서 가짜 응답을 쓸 수 있게 한다.
- `app.js`는 Finnhub 클라이언트와 저장소를 주입받는 `createApp()`을 내보내고, 실제 기동은 `index.js`에서 한다.

## 6. 데이터 모델

`data/portfolio.json`:

```json
{
  "version": 1,
  "holdings": [
    { "symbol": "SOFI", "shares": 500, "avgCost": 14.2 }
  ],
  "events": [
    { "id": "e_1727400000000", "title": "FOMC", "date": "2026-10-28", "note": "" }
  ]
}
```

**검증 규칙:**
- `symbol`: 대문자 1~10자이며 영문·숫자·`.`·`-`만 허용한다. 저장 시 대문자로 바꾸고, 중복은 허용하지 않는다.
- `shares`, `avgCost`: 0보다 큰 유한한 숫자(소수 허용).
- `date`: `YYYY-MM-DD` 형식. `title`: 1~60자. `note`: 200자 이하.

**저장 방식:** 임시 파일에 쓴 뒤 rename한다(원자적 쓰기). 파일이 없으면 빈 포트폴리오로 새로 만든다.

## 7. 서버 API

| 메서드·경로 | 설명 | 응답 요약 |
|---|---|---|
| `GET /api/portfolio` | 보유 종목 + 일정 | `{holdings, events}` |
| `POST /api/holdings` | 종목 추가(티커 존재 확인 포함) | 추가된 항목 + 회사명. 중복이면 409 |
| `PUT /api/holdings/:symbol` | 수량·평단가 수정 | 수정된 항목 |
| `DELETE /api/holdings/:symbol` | 종목 삭제 | 204 |
| `POST /api/events` · `PUT /api/events/:id` · `DELETE /api/events/:id` | 직접 입력 일정 관리 | 항목 / 204 |
| `GET /api/quotes?symbols=A,B` | 시세 | `{A: {price, change, changePct, prevClose, time, name, stale}}`, 실패 종목은 `error` |
| `GET /api/news?symbols=A,B` | 최근 7일 뉴스 | `{items: [{symbol, headline, source, url, datetime}], failed: [symbol]}` |
| `GET /api/earnings?symbols=A,B` | 앞으로 90일 실적 일정 | `{items: [{symbol, date, hour: "bmo"|"amc"|"dmh"|"", epsEstimate}], failed: [symbol]}` |
| `GET /api/fx` | USD→KRW | `{rate, date, stale}` |
| `GET /api/market-status` | 장 상태 | `{isOpen, session}` |
| `GET /api/health` | 키 설정 여부 등 | `{finnhubKey: "ok"|"missing"|"invalid"}` |

- 모든 오류 응답은 `{error: {code, message}}` 형식이며, `message`는 화면에 그대로 쓸 수 있는 한국어 문장이다.
- `stale: true`는 외부 호출에 실패해 캐시된 마지막 값을 돌려줬다는 뜻이다.

## 8. 계산 규칙 (`calc.js`)

종목별:
- 평가금액 = 수량 × 현재가
- 매입금액 = 수량 × 평단가
- 평가손익 = 평가금액 − 매입금액, 손익률 = 평가손익 ÷ 매입금액
- 오늘 등락액 = 수량 × (현재가 − 전일 종가)

합계:
- 합계는 가격이 있는 종목만 더하고, 가격이 한 번도 없었던 종목 수를 `excludedCount`로 돌려준다.
- 비중 = 종목 평가금액 ÷ 총 평가금액. 비중 합은 반올림 전 기준으로 100%다.
- 원화 환산 = 총 평가금액 × 환율.

표시는 금액을 소수 둘째 자리, 퍼센트를 소수 첫째 자리까지 한다. 계산은 반올림하지 않은 값으로 한다.

## 9. 디데이·시간 규칙 (`dday.js`, `market.js`)

- **실적발표 디데이:** 미국 동부 날짜를 기준으로, 오늘(미국 동부 날짜)과의 일수 차이로 센다.
- **한국시간 안내:** 장전(`bmo`)은 같은 날짜의 한국 밤, 장후(`amc`)는 다음 날 한국 아침으로 표시한다. 장중(`dmh`)이나 미정은 날짜만 표시한다.
- **직접 입력 일정:** 한국 날짜 기준으로 센다.
- **지난 일정:** 화면에서 숨기고 파일에는 남긴다.
- **장 상태:** 뉴욕 시간 평일 09:30–16:00을 장중으로 본다(서머타임은 `Intl`의 `America/New_York`으로 자동 처리). Finnhub 장 상태·휴장일 정보를 우선 쓰고, 실패하면 시간표 계산만으로 판정한다. 조기 폐장일은 Finnhub 정보가 있을 때만 반영한다.

## 10. 오류 처리

원칙: **틀린 숫자보다 오래된 숫자가 낫다.** 실패했다고 값을 0이나 빈칸으로 바꾸지 않고, 마지막 성공 값과 그 시각을 보여준다.

| 상황 | 동작 |
|---|---|
| API 키 없음/잘못됨 | 서버는 정상 기동. 화면 상단에 키 설정 안내 배너를 띄운다. 보유 종목 입력은 가능하다. |
| 429 한도 초과 | 지수 백오프(최대 60초). 그동안 캐시 값을 `stale`로 제공하고, 상단에 "지연" 표시. |
| 네트워크 오류 | 위와 같다. 숫자는 흐리게 처리하고 마지막 갱신 시각을 강조한다. |
| 특정 종목 시세 실패 | 해당 행에 ⚠ 표시와 마지막 값을 보여준다. 값이 한 번도 없으면 합계에서 빼고 "N개 종목 제외"를 표시한다. |
| Finnhub가 가격 0 반환 | 없는 티커로 보고 실패로 처리한다. |
| 없는 티커 추가 | 400, "찾을 수 없는 티커입니다". |
| 중복 티커 추가 | 409, 기존 행 수정 안내. |
| 입력값 오류 | 400, 필드별 한국어 메시지. |
| `portfolio.json` 파싱 실패 | 원본은 건드리지 않는다. 읽기 API는 오류를 반환하고 모든 쓰기를 거부한다. 화면에 복구 안내를 띄운다. |
| 포트 사용 중 | 콘솔에 포트 번호와 `.env`의 `PORT` 변경 방법을 출력하고 종료한다. |

## 11. 테스트

실제 Finnhub·Frankfurter는 테스트에서 호출하지 않고, 주입한 가짜 `fetch`를 쓴다. 러너는 `node --test`다.

- **calc:** 평가금액·손익·손익률, 비중 합 100%, 오늘 등락, 소수 수량, 보유 0개, 가격 없는 종목 제외와 `excludedCount`.
- **store:** 저장 후 재읽기 일치, 검증 규칙별 거부, 중복 거부, 파싱 실패 시 쓰기 거부와 원본 보존, 파일 없음 → 빈 포트폴리오.
- **market:** 평일 장중·장전·장후, 주말, 휴장일, 서머타임 시작·종료일.
- **finnhub:** TTL 안에서는 캐시 사용, 동시 요청 병합, 429 후 `stale` 캐시 반환, 가격 0 → 실패, 401 → 키 오류.
- **dday:** D-0, 장후 발표의 한국 날짜 +1, 90일 범위, 지난 일정 숨김.
- **routes:** `createApp()`에 가짜 클라이언트와 임시 저장 경로를 주입하고, 실제 포트로 띄워 각 엔드포인트의 정상·오류 응답을 확인한다.
- **수동 확인:** 실제 키로 기동해 화면을 한 번 확인한다(장중·장외 각 1회 권장).

## 12. 사용자가 준비할 것

1. Finnhub 무료 가입 후 API 키 발급(finnhub.io).
2. `.env.example`을 `.env`로 복사하고 `FINNHUB_API_KEY`에 키를 입력한다.
